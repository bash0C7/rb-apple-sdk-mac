## 残り blocker (T52 GREEN完成のため)

### T52 example 1-op-trigger bug

`examples/async_taskgroup.rb` で 3 個の NSBlockOperation を NSOperationQueue
に `addOperation(op)` で enqueue するが、 1 個だけしか callback fire しない。

trigger される op は実行ごとに変わる (ms=10 / ms=20 / ms=30 が混在で出現)。
他 2 個の block は Apple thread でも実行されない模様。

検証 candidate (次セッションで試行):

1. **T52k**: NSOperationQueue.maxConcurrentOperationCount setter mechanism
   - Swift 6 では `setMaxConcurrentOperationCount:` selector は obsoleted、
     property assignment (`queue.maxConcurrentOperationCount = N`) で操作する
   - Apple.discover の swift_property: は getter only。 setter 経路を新規実装
2. **T52l**: BlockOperation の retain lifecycle 確認
   - Ruby は raw int で proxy instance を保持、 Swift ARC への影響をデバッグ
   - 各 BlockOperation 生成直後に retain count を Apple Foundation の
     `CFGetRetainCount` で取って観察
3. **T52m**: 別 Apple framework primitive で代替検討
   - GCD の DispatchQueue.concurrentPerform 経路
   - NSThread を直接 spawn 経路
