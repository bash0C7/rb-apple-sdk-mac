# v1.2 — bootstrap! 原則 + Apple.discover 例外化

**Date**: 2026-05-09
**Status**: Design (awaiting implementation plan)
**Scope**: rb-apple-sdk-mac v1.2.0 release

---

## 1. Thesis & Principles

### 1.1 Thesis

`AppleSDKMac.bootstrap!` 1 行で macOS の任意の public framework symbol が Ruby method として叩ける状態になることが、 このジェムの principal な使い方。 `Apple.discover` は escape hatch であって、 通常コードには現れない。

### 1.2 Six principles

1. **bootstrap! ファースト** — `require "apple_sdk_mac"; AppleSDKMac.bootstrap!` の後、 `Apple::<Framework>::<Klass>.<method>` でどの API も呼べる
2. **Apple.discover は exception** — KB に居らへんもの (private framework / 第三者 framework / 自前 ObjC selector) の宣言だけに使う、 README に「これは escape hatch です」と明記
3. **静的 emitter が高速 path** — SQLite KB に確答が居る pattern は静的 template emit で deterministic に Swift glue を出す
4. **LLM safety net がカバー** — 静的 emitter で対応不能な pattern (未対応 marshaller / 未対応 kind / Swift bridge 名 mismatch) は automatic に LLM fallback に流れる。 broken Swift をそのまま swiftc に渡すことはしない
5. **examples は principle の例示** — examples/*.rb は bootstrap! 中心に書き直す。 `examples/discover_escape.rb` 1 個だけ「Apple.discover が必要な escape hatch ケース」を示す demo として残す
6. **experimental 自覚** — README L1 (タイトル直下) に「This gem is experimental」を必須化。 Ruby 4 Box (実験 flag) / macOS 26 Foundation Model on-device / LLM 由来 glue の確率性 / public API の v1.x shape 変更ありうる、 を明示

### 1.3 v1.2 design tenet

> **網羅性 > 速度**。 静的解決の漏れは前提、 LLM 安全網が常に網羅率を 100% に保つ。 速度は静的 emitter を後から厚くして稼ぐ。

### 1.4 v1.1.0 → v1.2.0 user 視点要約

|  | v1.1.0 | v1.2.0 |
|---|---|---|
| API 解決の標準形 | bootstrap! → 透過 dispatch (一部 KB miss あり) | bootstrap! → 透過 dispatch (Swift overlay 含む) |
| Apple.discover の位置付け | 3 ケースの escape hatch | 「principal には不要、 例外専用」と README で宣言 |
| KB scope | C/ObjC framework 中心 | Swift overlay framework 含む |
| 不明 pattern の挙動 | 静的 emitter が broken Swift → swiftc fail | 静的 emitter が察知 → LLM fallback |
| repo 構造 | rb-apple-sdk-mac + sibling rb-apple-sdk-knowledge | rb-apple-sdk-mac monorepo (knowledge/ + irb/ + mcp/ sub-gems) |
| Glue artifact / KB SQLite の場所 | `~/.cache/rb-apple-sdk-mac/...` | `<project_root>/.rb-apple-sdk-mac/...` (Bundler.root or Gemfile 走査) |

### 2.4 `<project_root>` 解決ロジック

優先順:

1. **Bundler.root** — `defined?(Bundler) && Bundler.respond_to?(:root)` で defensive に呼ぶ。 Rails app は `Gemfile` が app root に居て、 `bundle exec rails server` / `bundle exec rake ...` 経由なら `Bundler.root` は app root を返す
2. **Dir.pwd 上向き走査** — `Dir.pwd` から `Gemfile` または `gems.rb` を上向きに探して、 見つかった dir を返す
3. **どちらも見つからん場合** — `AppleSDKMac::ProjectRootError` raise (「project root を特定できへん。 Gemfile のある場所で実行してください」)

ENV var / `AppleSDKMac.configure` は両方落とす。 「Gemfile のあるとこで使う」を前提にする。

dir 名: `.rb-apple-sdk-mac/` (gem 名そのまま)。

### 2.5 新規 ingester の責務範囲 (Phase 3)

| ingester | 何を読む | 既存/新規 |
|---|---|---|
| ObjC framework importer | `*.framework/Headers/*.h` (clang AST) | 既存 |
| Swift framework importer | `*.swiftmodule/*.swiftinterface` (C bridge 中心) | 既存 |
| Swift overlay importer | `*.framework/Modules/*.swiftmodule/*.swiftinterface` (Swift native types: AVFoundation / Vision / SwiftUI 等) | ★ 新規 |

### 2.6 新規 emitter ロジック (Phase 4)

class_method 経路の Swift bridge naming に override テーブルを追加。 既存 heuristic (`<verb>With<Type>:` → init form) で間違える symbol を symbol-by-symbol で正解形に正す。 KB 側の `swift_imported_name` カラム優先、 取れない場合は emitter 側の override hash で fallback、 どちらもなければ heuristic、 全部 miss なら LLM 経由。

## 3. Marshaller 安全網 + IntMarshaller fix

### 3.1 現状の Marshaller out_param 棚卸し

| Marshaller | in_load | out 三点 (現在) | broken? trigger |
|---|---|---|---|
| String | ✓ | ✗ | (out_param 想定外) |
| **Int** | ✓ | **✗** | ✗ |
| **Bool** | ✓ | **✗** | ✗ |
| **Float** | ✓ | **✗** | ✗ |
| OpaqueRef | ✓ | ✓ | — |
| CFTypeRef | ✓ | ✓ | — |
| StructIn | ✓ | (in 専用) | ✓ |
| StructOut | (out 専用) | ✓ | — |
| StructInPointer | ✓ | (in 専用) | — |
| ArrayOfOpaqueRef | ✓ | ✗ | ✓ (route nil) |
| Callback / Block 系 | ✓ | ✗ | (out_param 想定外) |
| VoidPtrNilable | ✓ | ✗ | (template が is_out=false に矯正) |
| Variadic | ✓ | ✗ | (out_param 想定外) |

`✗` が並ぶ Int / Bool / Float が穴。 KB に `is_out_param=true` で来たときに base class の nil 戻りを使ってしまい、 broken Swift を吐いて swiftc に渡す事故が起こる。

### 3.2 安全網 (Phase 2)

`TemplateGenerator#generate` の C-function path に「marshaller の out 機能 vs param 要求」を事前 check する fence を入れる:

```ruby
return nil if marshallers.any? { |m|
  m.param[:is_out_param] && m.out_handling.nil?
}
```

(`out_handling` は section 7.1 で定義する単一 API。 旧 `out_init` / `out_addr` / `out_to_ruby` をひとまとめにした Hash を返すか nil。)

`nil` 戻り = 既存仕様で LLM fallback への routing が走る。 broken Swift が swiftc に渡る事故が消える。

副作用: 「LLM が初回 1.5〜3 秒、 1/3 確率で再試行」というレイテンシ特性で動く。 deterministic ではないが、 動く。 これが安全網の核心。

### 3.3 LLM 動作実証 (Phase 2 verify ゲート)

安全網を入れた直後の verification として、 CoreAudio の `AudioObjectGetPropertyDataSize` を bootstrap! 経由で叩いて、 LLM 経路が「動く Swift」を吐いて swiftc 通過することを E2E 確認する。

成功条件:

- `examples/audio_device_count.rb` (新規) が `bootstrap!` だけで実行できる
- 出力に audio device 数が出る
- `compile_history` row に LLM generator 経由の成功レコードが残る

失敗条件 (= Phase 2 を blocker 扱い):

- LLM が 6 retry 全部 off-format → 静的 emitter を先に作る判断 (Phase 3 倒置)

このゲートを通過してから Phase 3 (静的 emitter) に進む。

### 3.4 IntMarshaller out 実装 (Phase 3)

OpaqueRefMarshaller の out 三点セットを int 型用に書き直す。 ただし section 7.1 の単一 `out_handling` 形で:

```ruby
class IntMarshaller < Marshaller
  def in_load
    return nil if @param[:is_out_param]
    "let #{@param[:name]}: Int64 = rb_num2ll(argv[#{@index}])"
  end

  def call_arg
    return "&#{@param[:name]}" if @param[:is_out_param]
    ctype = scalar_type_token(@param[:type])
    return @param[:name] if ctype.nil? || ctype == "Int64"
    "numericCast(#{@param[:name]})"
  end

  def out_handling
    return nil unless @param[:is_out_param]
    ctype = scalar_type_token(@param[:type]) || "Int64"
    {
      init: "var #{@param[:name]}: #{ctype} = 0",
      addr: "&#{@param[:name]}",
      to_ruby: unsigned?(@param[:type]) \
        ? "rb_ull2inum(UInt64(#{@param[:name]}))"
        : "rb_ll2inum(Int64(#{@param[:name]}))"
    }
  end
end
```

### 3.5 Bool / Float marshaller の out 実装 (Phase 3 同時)

実 KB record で is_out_param=true で出てくるかどうかを Phase 3 序盤で grep:

```bash
sqlite3 .rb-apple-sdk-mac/knowledge/<sdk_version>/*.sqlite \
  "SELECT s.name, p.value FROM symbols s, json_each(s.parameters_json) p
   WHERE json_extract(p.value, '$.is_out_param') = 1
     AND json_extract(p.value, '$.kind') IN ('bool', 'float')"
```

ヒットした symbol があれば Bool/Float も同 pattern で `out_handling` 実装。 ゼロなら Int だけで Phase 3 完了。 安全網があるので bool/float out が後で必要になっても自動で LLM へ流れて事故らない。

## 4. KB ingester 拡張 + Emitter Swift bridge naming 補正

### 4.1 現状の KB ingest 範囲

- ingest 対象: macOS 26 SDK 同梱の `*.swiftinterface` 446 ファイル
- ObjC framework (Hypervisor / Security / CoreMIDI / CoreAudio など) の API はリッチ
- Swift overlay framework (Foundation / AppKit / AVFoundation / Vision / SwiftUI 系) は KB に空 (compiler 仕様で `.swiftinterface` に native Swift 型が出てこない)
- 結果として AVCaptureDevice / VNRecognizeTextRequest / SwiftUI View 等は KB lookup miss → bootstrap! の eager-define で method shell が生えへん

### 4.2 Phase 4a: Swift overlay ingester 追加

knowledge/ sub-gem の importer 群に Swift overlay 専用 ingester を追加。

**source の場所**:

```
$(xcrun --show-sdk-path)/System/Library/Frameworks/<FW>.framework/
  Modules/<FW>.swiftmodule/arm64-apple-macos.swiftinterface
```

これは既存 ObjC framework の `.swiftinterface` と同じ場所だが、 中身は「Swift native type 宣言 + `@objc` import」の二重構造。 既存 ingester が parse できているのは「`@objc` 由来の Foundation/CoreMIDI 系 API」だけで、 Swift native の `class func devices(for:)` 等は parse 漏れ。 ここを足す。

**parse 戦略**:

regex ベースで主要 Swift 宣言形 (`public class func`, `public init`, `public var`, `public func`) を行ベース抽出。 generic / async / throws / where 句で parse 不能な行は skip し、 LLM 安全網に任せる (網羅 > 速度の tenet 通り)。 swift-syntax ベースの完全 parse は v1.3 以降。

**新規 KB column** (knowledge/ schema 変更):

```sql
ALTER TABLE symbols ADD COLUMN swift_imported_name TEXT;
```

ObjC selector → Swift import name の対応 (例: `+devicesWithMediaType:` → `devices(for:)`) を ingest 時に解決して保存。 これがあれば emitter 側の bridge naming heuristic が不要になる。

**CACHE_SCHEMA bump**: KB の cache schema version を上げて、 既存ユーザの SQLite を自動再生成 trigger に。

### 4.3 Phase 4b: Glue emitter の Swift bridge naming 補正

現状 `swift_call_for_class_method` は selector 名 regex から init form を guess する heuristic 1 本のみ。 これが AVCaptureDevice 系で外れている。 修正は section 7.3 の `SwiftBridgeName.resolve` 値オブジェクトに集約:

```ruby
SwiftBridgeName.resolve(klass, selector, kc:)
# 内部で順に試す:
# 1. KB の swift_imported_name 経由
# 2. lib/apple_sdk_mac/glue_compiler/swift_bridge_overrides.rb の hash 経由
# 3. 既存 heuristic (`<verb>With<Type>:` → init form) 経由
# 4. nil (= 全部 miss → caller が template generate を nil 戻して LLM へ)
```

emitter の caller (`emit_objc_class_method`) は `SwiftBridgeName.resolve(...).swift_call_expression(args)` を呼ぶだけ。 3 階層を意識せん。

**安全網との関係**:

emitter が wrong naming の Swift を吐いたら swiftc fail。 section 7.2 の単一 retry 境界が template の Result を吸い上げて LLM 経由に流す。 v1.2 の網羅率を 100% に保つ最後のピース。

### 4.4 影響範囲

| 場所 | 変更内容 |
|---|---|
| knowledge/lib/.../importers/swift_overlay.rb | 新規、 regex parser |
| knowledge/lib/.../store.rb | `symbols.swift_imported_name` カラム追加、 CACHE_SCHEMA bump |

### 6.2 Error handling

| 経路 | 失敗 mode | 挙動 |

| bootstrap! | KB 未生成 | `AppleSDKKnowledge::SDK::CacheNotFoundError` 相当を raise、 README で `rake apple:knowledge:rebuild` を案内 |

### 6.3 Risks

1. **KB SQLite の per-project 化で初回コスト爆発** — `rake apple:knowledge:rebuild` は数分〜数十分。 README で明示。 自動 cross-project 共有はやらん (isolation 優先)
2. **Swift overlay ingester が parse miss** — regex parser で漏れがあっても LLM safety net で「初回 1.5〜3 秒の swiftc 待ち」止まり
3. **emitter override hash の保守負荷** — 長期的には KB column に寄せる、 override hash は「swift-syntax 完全 parse 化までの bridge」
4. **rb-apple-sdk-knowledge を消すと外部 user (もし居たら) が壊れる** — Phase 7 着手前に GitHub stars / fork 確認、 必要なら通知判断を user に
5. **Foundation Model on-device の retry レイテンシが UX を損ねる** — 安全網経由が常態化したシンボルがあると、 初回呼び出しが最大 18 秒待つ可能性。 compile_history を見て LLM 比率高い symbol を Phase 3 拡張で静的化 (継続改善ループ)
6. **Phase 7 destructive op を AI agent が独断で進める事故** — implementation plan で「ここで停止して user 確認」step を独立タスク化

## 7. Implementation discipline (内部 API 簡素化)

Feature を全部維持したまま、 内部実装の API surface と decision points を削る規律。

### 7.1 Marshaller の out 対応は単一 `out_handling` メソッド

各 kind が `out_init` / `out_addr` / `out_to_ruby` の 3 メソッドを別々に実装する形をやめ、 1 メソッドに集約する。

```ruby
class Marshaller
  # 戻り値: Hash {init: String, addr: String, to_ruby: String} か nil
  # nil = この marshaller は out_param 非対応 → 安全網が LLM へ流す
  def out_handling = nil
end
```

利点:

- 各 kind の out 実装が 1 ブロックで読める
- 安全網の事前 check が `marshallers.any? { |m| m.param[:is_out_param] && m.out_handling.nil? }` の 1 行
- 既存の OpaqueRef / CFTypeRef / StructOut の 3 メソッド実装も同形に整流 (REFACTOR commit)

### 7.2 GlueCompiler から LLM エントリは 1 箇所のみ

LLM が呼ばれる条件 ((a) template が nil、 (b) gate fail、 (c) swiftc fail) を 3 箇所別ブランチで持たず、 単一 retry 境界に集約:

```ruby
def compile(framework:, symbol:)
  result = try_template(framework, symbol)
  return result if result.success?
  # template が nil 戻し / gate fail / swiftc fail のいずれでも同じ経路
  try_llm(framework, symbol, prior_failure: result)
end
```

`try_template` の中で nil/gate/swiftc の 3 条件を Result で吸い上げ、 caller は `success?` だけ見る。

### 7.3 Emitter Swift bridge naming は値オブジェクト経由

KB column → override hash → 既存 heuristic の 3 階層を、 caller が知らないように `SwiftBridgeName` 値オブジェクトに閉じる:

```ruby
class SwiftBridgeName
  def self.resolve(klass, selector, kc:)
    from_kb(klass, selector, kc) ||
      from_override(klass, selector) ||
      from_heuristic(klass, selector)
  end
end
```

emitter caller は `SwiftBridgeName.resolve(klass, selector, kc:).swift_call_expression(args)` を呼ぶだけ。 3 階層を意識せん。 1 ファイル `lib/apple_sdk_mac/glue_compiler/swift_bridge_name.rb` に閉じる。

### 7.4 cache_dir は単一モジュール関数

`AppleSDKMac.cache_dir` 1 関数で Bundler.root → Dir.pwd 走査 → raise の 2 段だけ。 ENV var / configure path は提供しない。

```ruby
module AppleSDKMac
  def self.cache_dir
    root = bundler_root || gemfile_walk_up || (raise ProjectRootError, "...")
    File.join(root, ".rb-apple-sdk-mac")
  end
end
```
